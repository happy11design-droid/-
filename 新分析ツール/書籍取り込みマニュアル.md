# 書籍をNotebookLMに取り込み、判定用ルールブックと数値ルール表を作る手順

書籍のテキストデータ（1ページごとの.txt）を章ごとの.mdにまとめてNotebookLMに登録し、Claudeが自動で「判定用ルールブック」（原本と照合・修正済み）と「数値ルール表」を作るまでの手順。2026-09-26〜27に6冊（ミネルヴィニ、コナーズ、ワインスタイン、タープ、ボリンジャー、ラシュキ＆コナーズ）で実行した結果をもとにまとめた。

## 全体の流れ

| 段階 | 作業 | 担当 | 所要時間の目安 |
|---|---|---|---|
| A | 章リストを作る | 自分 | 10分 |
| B | 1ページごとの.txtを章ファイル（.md）に結合する | 自分（パソコンでスクリプトを実行） | 1分 |
| C | NotebookLMにノートブックを作り、章ファイルをソースに追加する | 自分 | 3分 |
| D | Claudeに「ノートブック『〇〇』で書籍の抽出を実行して」と頼む | 自分 | 1行 |
| D-1〜D-5 | 抽出 → 統合 → 照合 → 修正 → 数値ルール表 → 保存 → 後片付け | Claude（全自動） | 30分〜1時間 |

## 事前準備（最初の1回だけ）

### Python
- Windows: python.org からインストール。インストール時に「Add python.exe to PATH」にチェック。
- 確認: コマンドプロンプトで `python --version`。

### 作業フォルダ
例: `C:\ファイル\本の変換`

```
本の変換/
├── merge_chapters.py   ← 結合スクリプト（使い回す）
├── 章リスト.txt         ← 本ごとに作り直す
├── pages/              ← 1ページごとの.txtを入れる（本ごとに入れ替える）
└── out/                ← 章ファイルができる（本ごとに空にする）
```

`merge_chapters.py` はGitHubリポジトリの `tools/merge_chapters.py` と同じもの。メモ帳に貼り付けて「すべてのファイル」「UTF-8」で保存する。

**⚠ 実際に起きた失敗**: メモ帳が `.txt` を付けて `merge_chapters.p.txt` と保存していた。`dir` で確認し、違っていたら `ren merge_chapters.p.txt merge_chapters.py` で直す（2冊目以降は不要）。

## A. 章リストを作る

1. 目次のページの.txtを開き、章の一覧を確認する。
2. 各章が始まるページの**ファイル名の番号**を調べる（印刷されたページ番号ではない）。
3. `章リスト.txt` に「番号 半角スペース 章タイトル」を1行1章で書く。

```
1 はじめに
12 第1章 〇〇〇〇
38 第2章 〇〇〇〇
```

- 本の最後（あとがき・索引・用語集・付録）を別の行にしたい場合は1行足す。
- 目次の読み取りが面倒なら、目次の.txtを1つだけClaudeに貼れば章リストを作ってくれる。

## B. 章ファイルを作る

1. エクスプローラーで `C:\ファイル\本の変換` を開き、アドレス欄に `cmd` と入力してEnter。
   - **⚠ 何度も起きた失敗**: `C:\Users\a>` のまま実行すると `can't open file 'C:\Users\a\merge_chapters.py'` になる。その場合は `cd /d "C:\ファイル\本の変換"` で移動する。
2. `pages` を今回の本の.txtだけにし、`out` を空にする。
3. 実行する。
```
python merge_chapters.py pages 章リスト.txt out
```
4. `01_〜.md: p.1〜 6ページ` のような行が章の数だけ出れば成功。ページ数の合計と、極端に少ない・多い章がないかを確認する。

章ファイルにはページごとに `<!-- p.12 -->` が入り、NotebookLMの出典「（p.〇）」はこの番号（＝ファイル名の番号）になる。

**本のテキストデータはGitHubに置かない**（著作権）。結合は自分のパソコンで行い、NotebookLMにだけアップロードする。

## C. NotebookLMに登録する

1. NotebookLMで「新規作成」→「ファイルをアップロード」→ `out` の全ファイルを選ぶ。
2. ノートブック名を「書名_著者名」にする（例: `ボリンジャーバンド入門_ジョン A ボリンジャー`）。
   - **⚠ 名前に「Claude」を入れない。** 今の分析ツールは名前に「Claude」を含むノートブックを自動で分析対象にする。
3. 全ページが1つになったファイルは追加しない（章ファイルと重複する）。

## D. Claudeに依頼する

> ノートブック「〇〇」で書籍の抽出を実行して

Claudeは以下を一括で実行し、最後に結果を報告する（2026-09-26以降は途中確認なし、`抽出_` の削除も事前承認済みの運用）。

### Claudeが実行するコマンド
```bash
# 認証（チャート分析.txt 手順A。タイムアウトしても既存の認証が有効なことが多い）
# 全工程を順に実行（<作業ディレクトリ> はスクラッチパッド内）
A=(--notebook "〈ノートブック名〉" --book "〈書名（著者）〉" --out <作業ディレクトリ>)
for ph in chapters rulebook verify revise table; do tools/extract_book.sh $ph "${A[@]}" || break; done
```

### D-1. 章ごとの抽出（`chapters`）
- 章ファイル（`数字2桁_` で始まるソース）を1つずつ対象に、3章ずつ並行で依頼する。
- **18ページを超える章はページ範囲で自動分割**して依頼する。
- 回答の最終行「未出力の節: なし／〇〇」を見て、打ち切りなら続きを自動で依頼する。最終行そのものがなければ範囲を半分にして依頼し直す。
- NotebookLMの引用番号 `[1-8]` は自動で除去し、`抽出_〈章ファイル名〉` というソースとして登録する。

### D-2. 判定用ルールブックへの統合（`rulebook`）
- `抽出_` のソースだけを対象に、章の順ではなく判定の順に並べ替えたルールブックを、前半（項目1〜6）と後半（項目7〜12）の2回で作り、`判定用ルールブック` として登録する。

### D-3. 原本との照合（`verify`）
- 章ごとに「原本の章＋ルールブック」を照合させ（食い違い・漏れ）、最後に1冊全体で「原本に根拠のない記述」を確認させる。
- 全文は作業ディレクトリの `照合結果.md`。Claudeが NotebookLM のメモ「照合結果（手順3）」として保存する。

### D-4. 修正（`revise`）
- 照合結果を一時ソース「照合結果」として登録し、修正版を前半・後半で作らせて `判定用ルールブック` を差し替え、指摘が解消されたかを確認させ、一時ソースを削除する。
- 修正の方針（2026-09-26決定）: 食い違い・根拠のない記述はすべて直す。漏れは条件や数値で判定できる売買ルールだけ追加し、心構え・精神論は追加しない。
- 確認で未解消が数件残った場合（コナーズで2件）は、Claudeがその箇所だけ文字列を直接直して差し替える。

### D-5. 数値ルール表（`table`）
- ルールブックから数値で判定できるルールだけを表にする。
- Claudeが冒頭にフロントマターと注記を付け、GitHubの `書籍ルール/〈著者〉_ルール表.md` と Obsidian の `株式分析/書籍/`（フォルダID `1_CFc5zom-nP7gzTRXVkM5VMUf6yCEHdn`、`text/markdown`・変換なし）に保存する。

### 後片付け
- 全工程が成功したら `抽出_` のソースを削除する。ノートブックは「原本の章ファイル＋判定用ルールブック」だけになる。
  - 理由: 抽出結果は修正されていないため誤りが残っている可能性があり、原本・ルールブックと重複して検索の邪魔になるため。

## NotebookLMへの指示内容（tools/書籍抽出/ のプロンプト）

| ファイル | 使う段階 | 対象ソース | 指示の要点 |
|---|---|---|---|
| `1_章抽出.txt` | D-1 | 章ファイル1つ | 12項目（主題／相場環境・適用条件／指標の定義／エントリー条件／見送る条件・例外／損切り／利確・手じまい／資金管理／保有期間／ダマシの回避／統計・検証結果／具体例）を抽出。ソースの内容だけ、全項目に「（p.〇）」、数値ルールは原文を「」で引用、明示のない箇所は「著者は明示していない」、【ルール】【例】【意見】で区別、最終行に「未出力の節」。 |
| `1b_続き.txt` | D-1 | 章ファイル1つ | 打ち切られた節だけを同じ基準で抽出。 |
| `2_ルールブック.txt` | D-2 | `抽出_` 全部 | 12項目（全体像／適用してよい・いけない相場環境／銘柄選定／エントリーのチェックリスト（必須・推奨を区別）／見送る条件／注文方法／損切り／利確・手じまい／資金管理／保有期間／統計・検証結果／著者が明示していない事項）に並べ替え。出典ページを残し、章で異なる記述は両方残して「矛盾あり」。 |
| `3_照合.txt` | D-3 | 原本の章1つ＋ルールブック | その章についての ①食い違い（原文を引用）②漏れている売買ルール。具体例の細部や心構えは挙げない。 |
| `3b_根拠確認.txt` | D-3 | 原本全部＋ルールブック | ルールブックの記述のうち原本に根拠がないもの（出典ページの原文に書かれていないものを含む）。「矛盾あり」の注記そのものは対象外（コナーズで11か所すべて消えたため2026-09-26に追加）。 |
| `3c_修正.txt` | D-4 | ルールブック＋照合結果 | 上記の修正方針で修正版を出力。指摘のない記述は表現を変えずに残す。 |
| `3d_修正確認.txt` | D-4 | 修正版＋照合結果 | 未解消の食い違い・根拠のない記述と、追加されていない売買ルールの一覧。 |
| `4_ルール表.txt` | D-5 | ルールブック | ルール名・種類・指標・期間・条件・注文方法・出典の表。ソースにない値は空欄。 |

## 注意事項と実際に起きたトラブル

| 症状 | 原因と対処 |
|---|---|
| `empty response from API`（どの質問も空で返る） | NotebookLMの質問回数の上限。1冊で約35〜40回質問する。無料版（1日50回）では1冊目の途中で発生し、有料プランにして解消。有料プランでも1日に約175回（5冊分）質問したところで上限に達し、約2時間半後（4:28）に解除された。解除時刻に `send_later` で自動再開を予約すれば、パソコンの電源を切っていても続きから進む。 |
| 「途中で打ち切られた可能性」という警告なのに中身は完結している | NotebookLMが最終行を簡体字で「未出力の节」と書いた。2026-09-27に `last_line` で「节」を「節」にそろえるよう修正済み。 |
| NotebookLMのメモ保存（`nlm note create`）が `bad-args` で失敗 | ほかのコマンドと1行でつなげると起きる。単独で再実行すれば成功する。 |
| 認証（`nlm auth`）がタイムアウト | 既存の認証がまだ有効なことが多い。短い質問を1つ送って確認する。Googleのログイン自体が切れている場合は `チャート分析.txt` 手順A-4（VMのChromeへ再ログイン、スマートフォンでも可）。 |
| ノートブックが見つからない | 名前の打ち間違い、またはNotebookLM専用アカウント以外で作った。 |
| ページ番号が1400番台など大きい | ページファイルの名前の番号がそのまま出典になるため。問題はない（ボリンジャーで発生、ルール表の冒頭に注記）。 |

- 作業ディレクトリ（スクラッチパッド）はセッション終了で消える。残るのは NotebookLM（原本・ルールブック・照合結果メモ）、GitHub（ルール表・スクリプト）、Obsidian（ルール表・このマニュアル）。
- 本の要約（抽出結果・ルールブック・照合結果）はGitHubに置かない。
