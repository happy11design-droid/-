# テーマ監視・スイング分析 手順書（下書き）

半導体・AIなど「今旬のテーマ」の銘柄だけを毎日監視し、条件がそろった銘柄だけを著者のノートブックに判定させる。
今の分析ツール（`チャート分析.txt`、ユーザーが選んだ個別銘柄の分析）とは別に動かす。

## 0. 守ること

- **個別銘柄の判定（買い／見送り、逆張りか順張りか、どこで利確・損切りするか）は著者のノートブックが行う。Claudeは行わない。** Claudeの役割は、数値の計算・事実の収集・候補の抽出・送信・回答の全文表示に限る（`CLAUDE.md` と同じ原則）。
- **テーマの移り変わりの判定も著者に任せる。** Claudeはテーマごとの数値（ヒートマップの騰落率、テーマの株価の30週線の位置など）を事実として渡すだけで、「テーマが終わった」とは判定しない。
- 著者に渡すのは数値と事実だけ。Claudeの解釈（相場天気予報の相場観を含む）は混ぜない。
- スクリプトで計算できる条件はスクリプトで計算し、「条件を満たす／満たさない」と数値を事実として渡す（画像の読み違いを防ぐ）。本に数値がない部分は「マニュアルに規定なし」と明記し、Claudeが数値を決めない。
- 著者ノートブックへの質問は1日約175回が上限。候補が多い日も、1銘柄ずつではなく、複数銘柄を1回にまとめて送る。

## 1. 使う著者と役割

| 役割 | ノートブック | 使う理由（バックテスト・ソースの根拠） |
|---|---|---|
| テーマ・相場全体の局面（ステージ1〜4） | テクニカル投資の基本講座_スタン ウエスタイン | 30週線の位置と傾きで局面を判定する本。テーマの株価をまとめた指数にも同じ判定を当てる |
| 順張り（上昇中のさらなる上昇） | ミネルヴィニの成長株投資法 | トレンドテンプレート＋出来高を伴う上抜け・利確20%が、2015〜2026年のS&P500で前半・後半とも安定してプラス（`バックテスト結果/ミネルヴィニ・ワインスタイン.md`） |
| 逆張り（上昇前の押し目） | ボリンジャーバンド入門 | メソッドIII（%b<0.05かつ21日II%>0）が前半・後半とも安定してプラス。下落局面でも有効（`バックテスト結果/ラシュキ・ボリンジャー.md`） |
| 逆張り（短期の売られすぎ） | コナーズの短期売買入門 | 相場全体が売られた日に優位性が集中（`バックテスト結果/コナーズ.md`） |
| リスク・建玉 | 新版 魔術師たちの心理学_バン K タープ | 1トレードのリスク2%・損切り15%から建玉を逆算（ユーザー決定） |

- ラシュキの日足パターンは、バックテストでどれもマイナスだったため、単独の仕掛けには使わない。
- **Claude_ちょる子は新ツールの判定には使わない**（ユーザー決定 2026-09-27）。「テーマに沿った業界トップ企業を決めて毎日定点観測する」という銘柄選びの考え方だけを、監視銘柄の作り方に取り入れた【出典: 投資家ちょる子_詳細マニュアル】。ちょる子に見てもらいたい銘柄は、既存の `チャート分析.txt` で分析する。
- 著者の割り当ては、監視銘柄での直近3年のバックテスト（`バックテスト結果/テーマ監視銘柄・直近3年.md`）の結果で見直す。
- 著者ノートブックの名前に「Claude」を付けていないので、今の分析ツールの対象にはならない。新ツールではこの表のノートブックを使う。

## 2. 毎日の流れ（引け後＝日本時間の朝）

### 手順T1: データの取得（スクリプト。数秒〜数十秒）
1. 相場全体: `tools/market_data.py macro`（NYダウ・NASDAQ・SOX指数・ドル円・金利・CNN Fear & Greed Index）。
2. ヒートマップ: Finviz の公開ヒートマップ（S&P500）の1日・1週・1カ月・3カ月・6カ月・1年の騰落率。
3. 監視銘柄（`テーマ監視銘柄.md`、約90銘柄）の日足と指標（作成予定のスクリプト）。

### 手順T2: テーマの強さと移り変わり（数値の計算はスクリプト、判定は著者）
- スクリプトが計算する事実:
  - テーマごと（半導体・製造装置・サーバー／ストレージ・光通信・電力部品・AIソフト）の騰落率（中央値）と、S&P500の全セクター・業種の中での順位（1週・1カ月・3カ月・6カ月・1年）。
  - テーマごとの株価指数（監視銘柄の等金額平均）の30週線の位置と傾き。
  - テーマの外で強くなっている業種（ヒートマップの上位で、監視銘柄に入っていない業種と代表銘柄）。
- 判定: ワインスタインのノートブック（テーマ指数のステージ）。ニュースはサブエージェントがWeb検索で集める（`tools/データ収集指示.md` と同じ方式）。
- 別のテーマへの移行が示されたら、監視銘柄の入れ替えを**ユーザーに提案する**（一覧はユーザーが編集する）。

### 手順T3: 候補の抽出（スクリプト。条件を満たした銘柄だけを次へ）
条件を1つでも満たした銘柄を候補とし、満たした条件と数値を一覧にする。候補がない日は著者に送らない。

| 種類 | 条件 | 出典 |
|---|---|---|
| 逆張り（ボリンジャー） | %b < 0.05 かつ 21日II% > 0（メソッドIII） | ボリンジャー ルール表 p.1589-1590 |
| 逆張り（コナーズ） | 200日線より上で、2日累積RSI(2) ≦ 10 | コナーズ ルール表 p.24 |
| 順張り（ミネルヴィニ） | トレンドテンプレート1〜8を満たし、ベースの高値を出来高2倍で上抜け | ミネルヴィニ ルール表 p.44, p.121 |

### 手順T4: 著者への送信と回答の表示
1. 候補ごとに、手順T1〜T3の数値、チャート画像（`tools/market_data.py ticker` で作成）、ニュース（サブエージェント）をまとめる。
2. 送り先:
   - 逆張りの候補 → ボリンジャー、コナーズ
   - 順張りの候補 → ミネルヴィニ
   - 建玉はスクリプトが計算する（リスク2%・損切り15%、タープの考え方）。タープのノートブックには毎日は聞かない
3. 各著者の回答を全文表示する。Claudeは回答を要約・改変しない。
4. 判定用プロンプトは今の `送信プロンプト雛形.txt` の考え方（著者のチェックリストに当てはめ、規定がない事項は「マニュアルに規定なし」）を使い、「冷徹な審査官」調はやめる（引き継ぎ資料の設計方針3）。雛形は別途作る。

### 手順T5: 記録
- 結果をObsidianに保存する（`保存・週次レビュー・QA.txt` の手順7と同じ方式、保存先は新ツール用のフォルダ）。
- 著者の判定とその後の値動きを記録し、週次レビューで「どの著者の判定が当たったか」を集計する。形の判断（ローソク足の形、VCP、ステージ）はバックテストできないため、この運用記録で評価する。

## 3. まだ決まっていないこと

1. ~~要確認の銘柄~~ → すべて入れ、約90銘柄に広げた（ユーザー決定 2026-09-27、100銘柄程度まで可）。
2. ~~通知の方法~~ → 毎朝のRoutineで自動実行する（ユーザー決定 2026-09-27）。
3. 1日に詳しく分析する候補の上限（案: 条件の当てはまりが強い順に5銘柄）。

## 4. 次の作業

1. 監視銘柄の日足・指標・候補抽出のスクリプト（手順T1-3・T3）。
2. テーマの強さのスクリプト（Finvizのヒートマップ＋テーマ指数の30週線、手順T2）。
3. 監視銘柄での直近3年のバックテスト（**監視銘柄は今の時点で選んでいるため成績は実際より良く出る。手法どうしの比較に使う**）。
4. 著者への送信プロンプトの雛形。
