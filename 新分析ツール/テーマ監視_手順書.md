# テーマ監視・スイング分析 手順書（下書き）

半導体・AIなど「今旬のテーマ」の銘柄だけを毎日監視し、条件がそろった銘柄だけを著者のノートブックに判定させる。
今の分析ツール（`チャート分析.txt`、ユーザーが選んだ個別銘柄の分析）とは別に動かす。

## 0. 守ること

- **個別銘柄の判定（買い／見送り、逆張りか順張りか、どこで利確・損切りするか）は著者のノートブックが行う。Claudeは行わない。** Claudeの役割は、数値の計算・事実の収集・候補の抽出・送信・回答の全文表示に限る（`CLAUDE.md` と同じ原則）。
- **テーマの移り変わりの判定も著者に任せる。** Claudeはテーマごとの数値（ヒートマップの騰落率、テーマの株価の30週線の位置など）を事実として渡すだけで、「テーマが終わった」とは判定しない。
- 著者に渡すのは数値と事実だけ。Claudeの解釈（相場天気予報の相場観を含む）は混ぜない。
- スクリプトで計算できる条件はスクリプトで計算し、「条件を満たす／満たさない」と数値を事実として渡す（画像の読み違いを防ぐ）。本に数値がない部分は「マニュアルに規定なし」と明記し、Claudeが数値を決めない。
- 著者ノートブックへの質問は1日約175回が上限。候補が多い日も、1銘柄ずつではなく、複数銘柄を1回にまとめて送る。

## 1. 使う著者と役割

| 役割 | ノートブック | 使う理由（バックテスト・ソースの根拠） |
|---|---|---|
| テーマ・相場全体の局面（ステージ1〜4） | テクニカル投資の基本講座_スタン ウエスタイン | 30週線の位置と傾きで局面を判定する本。テーマの株価をまとめた指数にも同じ判定を当てる |
| 順張り（上昇中のさらなる上昇） | ミネルヴィニの成長株投資法 | トレンドテンプレート＋出来高を伴う上抜け・利確20%が、2015〜2026年のS&P500で前半・後半とも安定してプラス（`バックテスト結果/ミネルヴィニ・ワインスタイン.md`） |
| 逆張り（上昇前の押し目） | ボリンジャーバンド入門 | メソッドIII（%b<0.05かつ21日II%>0）が前半・後半とも安定してプラス。下落局面でも有効（`バックテスト結果/ラシュキ・ボリンジャー.md`） |
| 逆張り（短期の売られすぎ） | コナーズの短期売買入門 | 相場全体が売られた日に優位性が集中（`バックテスト結果/コナーズ.md`） |
| リスク・建玉 | 新版 魔術師たちの心理学_バン K タープ | 1トレードのリスク2%・損切り15%から建玉を逆算（ユーザー決定） |

- ラシュキの日足パターンは、バックテストでどれもマイナスだったため、単独の仕掛けには使わない。
- **Claude_ちょる子は新ツールの判定には使わない**（ユーザー決定 2026-09-27）。「テーマに沿った業界トップ企業を決めて毎日定点観測する」という銘柄選びの考え方だけを、監視銘柄の作り方に取り入れた【出典: 投資家ちょる子_詳細マニュアル】。ちょる子に見てもらいたい銘柄は、既存の `チャート分析.txt` で分析する。
- 著者の割り当ては、監視銘柄での直近3年のバックテスト（`バックテスト結果/テーマ監視銘柄・直近3年.md`）の結果で見直す。
- 著者ノートブックの名前に「Claude」を付けていないので、今の分析ツールの対象にはならない。新ツールではこの表のノートブックを使う。

## 2. 毎日の流れ（引け後＝日本時間の朝）

### 手順T1〜T3: データの取得・テーマの状態・候補の抽出（スクリプト1本、約20秒）
```bash
tools/theme_scan.py "$D/scan.md"
```
- 監視銘柄（`テーマ監視銘柄.md`、87銘柄）とS&P500の日足（2年分）を取得し、次を書き出す。数値と事実だけで、売買の判断はしない。
  1. グループごとの騰落率（1週・1カ月・3カ月）と順位、50日線より上の銘柄の割合。
  2. テーマ指数（監視銘柄の等金額平均）の30週線による局面（ワインスタインのステージの近似）と、早めの警告（監視銘柄のうち50日線より上の割合が40%未満、かつテーマ指数が50日線より下）。
  3. Finvizの業種別の騰落率（全米）の上位と、テーマの業種の順位（テーマの外への移り変わりの確認）。
  4. 候補と注文の目安（下の表）、次回決算予定日（14日以内なら「決算が近い」と表示）。
- 相場全体の数値は `tools/market_data.py macro`（NYダウ・NASDAQ・SOX・ドル円・金利・CNN Fear & Greed Index）。

候補の条件（`バックテスト結果/テーマ監視銘柄・直近3年.md` で採用したもの）:

| 種類 | 条件 | 注文の目安 | 出典 |
|---|---|---|---|
| 逆張り（ボリンジャー メソッドIII） | %b < 0.05 かつ 21日II% > 0 | 翌日の寄り付きで買い、損切り15%、引けで上部バンド以上になった翌日の寄り付きで手じまい | ボリンジャー ルール表 p.1589-1590 |
| 順張り（ミネルヴィニ） | トレンドテンプレート1〜8、直前50日のベース（幅35%以内）の高値を出来高2倍で上抜け | 翌日の寄り付きで買い（寄り付きがピボット+3%を超えたら見送り）、損切り15%、引けで50日線を割った翌日の寄り付きで手じまい | ミネルヴィニ ルール表 p.44, p.98, p.118-122 |
| 順張り（ワインスタイン 10週） | 週足の終値が直前10週の高値を出来高2倍で上抜け、10週線が上向き（週の最終取引日だけ判定） | 翌日の寄り付きで買い、損切り15%、週足の終値が10週線を割ったら手じまい | ワインスタイン ルール表 p.12-13, p.67 |

- 採用しなかったもの（バックテストの結果）: ラシュキの日足パターン（NR7はマイナス、聖杯・アンチは弱い）、ボリンジャーのメソッドI、コナーズのダブル7（売買コストを厳しめに見ると大きく悪化）、同じグループの保有の上限（改善しなかった）、警告中に新しい買いを止めること（押し目買いの成績が大きく下がった）。
- 押し目（ボリンジャーIII）はRS≧80の銘柄の方が成績が安定していた（候補の表にRSを出す）。

### 手順T4: 著者への送信と回答の表示
1. 候補ごとに `tools/market_data.py ticker` で数値データ（直近10日の日足・指標）を作り、ニュース（サブエージェント）を足す。
   `tools/build_theme_prompt.py "$D/scan.md" "$D/out" <種類の語> <ティッカー>:<データファイル> ...` で、`テーマ監視_送信プロンプト雛形.txt` に差し込む（12,000文字ごとに分けて、1回に3銘柄程度をまとめて送る）。
2. 送り先:
   - 逆張りの候補 → ボリンジャー
   - 順張りの候補 → ミネルヴィニ（ワインスタイン10週の候補はワインスタイン）
   - テーマの局面 → ワインスタイン（テーマ指数のステージと警告の数値を渡す）
   - 建玉はスクリプトが計算する（リスク2%・損切り15%、タープの考え方）。タープのノートブックには毎日は聞かない
3. 各著者の回答を全文表示する。Claudeは回答を要約・改変しない。
4. **未決（ユーザーの判断待ち）**: 試験送信（2026-09-01時点のLRCX・TER・SHOP）で、ボリンジャーのノートブックは3銘柄とも「反発の確認がない」として様子見と判定した。ところが「シグナル後の最初の反発の陽線を待って買う」をバックテストすると、年率43%→19%、最大下落25%→31%と悪化した。著者が様子見とする場面が、バックテストでもっとも利益の出た買い場だった。判定の役割を「著者が買う・見送るを決める」にするか、「バックテストで採用したルールが買いを決め、著者はルール違反・決算・悪材料による見送りだけを判定する」にするかを決める必要がある。

### 手順T5: 記録
- 結果をObsidianに保存する（`保存・週次レビュー・QA.txt` の手順7と同じ方式、保存先は新ツール用のフォルダ）。
- 著者の判定とその後の値動きを記録し、週次レビューで「どの著者の判定が当たったか」を集計する。形の判断（ローソク足の形、VCP、ステージ）はバックテストできないため、この運用記録で評価する。
