# テーマ監視・スイング分析 手順書（下書き）

半導体・AIなど「今旬のテーマ」の銘柄だけを毎日監視し、条件がそろった銘柄だけを著者のノートブックに判定させる。
今の分析ツール（`チャート分析.txt`、ユーザーが選んだ個別銘柄の分析）とは別に動かす。

## 0. 守ること

- **買いの条件は、ユーザーが採用した売買ルール（下の手順T3の表。バックテストで検証済み）が決める。著者のノートブックは「注文を止める理由」だけを判定する**（ユーザー決定 2026-09-27、方式B）。止める理由は、本が禁じる形・状況、決算など避けるべき時期、悪材料の3つ。本が必須と明記していない「確認を待つ」などの追加条件では止めない（確認を待つとバックテストの成績が大きく下がったため）。
- **Claudeは売買の判断をしない。** 役割は、数値の計算・事実の収集・候補の抽出・送信・回答の全文表示に限る。テーマの移り変わりも、Claudeは数値を渡すだけで、判定はワインスタインのノートブックが行う。
- 著者に渡すのは数値と事実だけ。Claudeの解釈（相場天気予報の相場観を含む）は混ぜない。
- 急騰・急落そのものは売買の合図にしない（原因の調査のきっかけにする）。
- 著者ノートブックへの質問は1日約175回が上限。候補・保有銘柄は、著者ごとに3銘柄程度をまとめて1回で送る。

## 1. 使う著者と役割

| 役割 | ノートブック | 使う理由（バックテスト・ソースの根拠） |
|---|---|---|

| 順張り（上昇中のさらなる上昇） | ミネルヴィニの成長株投資法 | トレンドテンプレート＋出来高を伴う上抜け・利確20%が、2015〜2026年のS&P500で前半・後半とも安定してプラス（`バックテスト結果/ミネルヴィニ・ワインスタイン.md`） |
| 逆張り（上昇前の押し目） | ボリンジャーバンド入門 | メソッドIII（%b<0.05かつ21日II%>0）が前半・後半とも安定してプラス。下落局面でも有効（`バックテスト結果/ラシュキ・ボリンジャー.md`） |
| 逆張り（短期の売られすぎ） | コナーズの短期売買入門 | 相場全体が売られた日に優位性が集中（`バックテスト結果/コナーズ.md`） |

- ラシュキの日足パターンは、バックテストでどれもマイナスだったため、単独の仕掛けには使わない。

- 著者の割り当ては、監視銘柄での直近3年のバックテスト（`バックテスト結果/テーマ監視銘柄・直近3年.md`）の結果で見直す。
- 著者ノートブックの名前に「Claude」を付けていないので、今の分析ツールの対象にはならない。新ツールではこの表のノートブックを使う。

## 2. 毎日の流れ（引け後＝日本時間の朝）

### 手順T1〜T3: データの取得・テーマの状態・候補の抽出（スクリプト1本、約20秒）
```bash
tools/theme_scan.py "$D/scan.md"
```
- 監視銘柄（`テーマ監視銘柄.md`、87銘柄）とS&P500の日足（2年分）を取得し、次を書き出す。数値と事実だけで、売買の判断はしない。
  1. グループごとの騰落率（1週・1カ月・3カ月）と順位、50日線より上の銘柄の割合。
  2. テーマ指数（監視銘柄の等金額平均）の30週線による局面（ワインスタインのステージの近似）と、早めの警告（監視銘柄のうち50日線より上の割合が40%未満、かつテーマ指数が50日線より下）。
  3. Finvizの業種別の騰落率（全米）の上位と、テーマの業種の順位（テーマの外への移り変わりの確認）。
  4. 候補と注文の目安（下の表）、次回決算予定日（14日以内なら「決算が近い」と表示）。
- 相場全体の数値は `tools/market_data.py macro`（NYダウ・NASDAQ・SOX・ドル円・金利・CNN Fear & Greed Index）。

候補の条件（`バックテスト結果/テーマ監視銘柄・直近3年.md` で採用したもの）:

| 種類 | 条件 | 注文の目安 | 出典 |
|---|---|---|---|
| 逆張り（ボリンジャー メソッドIII） | %b < 0.05 かつ 21日II% > 0 | 翌日の寄り付きで買い、損切り15%、引けで上部バンド以上になった翌日の寄り付きで手じまい | ボリンジャー ルール表 p.1589-1590 |
| 順張り（ミネルヴィニ） | トレンドテンプレート1〜8、直前50日のベース（幅35%以内）の高値を出来高2倍で上抜け | 翌日の寄り付きで買い（寄り付きがピボット+3%を超えたら見送り）、損切り15%、引けで50日線を割った翌日の寄り付きで手じまい | ミネルヴィニ ルール表 p.44, p.98, p.118-122 |
| 順張り（ワインスタイン 10週） | 週足の終値が直前10週の高値を出来高2倍で上抜け、10週線が上向き（週の最終取引日だけ判定） | 翌日の寄り付きで買い、損切り15%、週足の終値が10週線を割ったら手じまい | ワインスタイン ルール表 p.12-13, p.67 |

- 採用しなかったもの（バックテストの結果）: ラシュキの日足パターン（NR7はマイナス、聖杯・アンチは弱い）、ボリンジャーのメソッドI、コナーズのダブル7（売買コストを厳しめに見ると大きく悪化）、同じグループの保有の上限（改善しなかった）、警告中に新しい買いを止めること（押し目買いの成績が大きく下がった）。
- 押し目（ボリンジャーIII）はRS≧80の銘柄の方が成績が安定していた（候補の表にRSを出す）。

### 手順T4: ニュースの調査・著者への送信・回答の表示
1. **ニュースの調査（サブエージェント1件）**: `新分析ツール/ニュース調査指示.md` を読ませ、scan.md の「急騰・急落した銘柄」「保有銘柄」「候補」の原因・ニュース・悪材料を調べて `$D/news.md` に書かせる。メインでWeb検索はしない。
2. **数値データ**: 候補と保有銘柄ごとに `tools/market_data.py ticker <ティッカー> "$D"`（直近10日の日足・指標）。
3. **プロンプトの組み立て**: 著者ごとに
   `tools/build_theme_prompt.py "$D/scan.md" "$D/out_<著者>" <種類の語> --news "$D/news.md" <ティッカー>:"$D/<ティッカー>_data.txt" ...`
   （種類の語: ボリンジャー／ミネルヴィニ／ワインスタイン。候補と、そのルールで買った保有銘柄が入る。12,000文字ごとに分けて書き出す）
4. **送り先**:
   - ボリンジャーIIIの候補・保有銘柄 → ボリンジャーバンド入門
   - ミネルヴィニの候補・保有銘柄 → ミネルヴィニの成長株投資法
   - ワインスタイン10週の候補・保有銘柄 → テクニカル投資の基本講座（ワインスタイン）
   - テーマの局面（scan.md 1〜3節とテーマ全体のニュース） → ワインスタイン（プロンプトの雛形は運用開始時に作る）
   - 候補も保有銘柄もない日は、テーマの局面だけを送る。
5. **回答の表示**: 各著者の回答を全文表示する。Claudeは回答を要約・改変しない。候補は【注文する／見送る】、保有銘柄は【保有を続ける／早めに手じまう】で返ってくる。
6. **注文**: 【注文する】の候補は、scan.md の「注文の目安」どおりに翌営業日の寄り付きで注文し、同時に損切りの逆指値（買値の15%下）を置く。買ったら `新分析ツール/保有銘柄.md` に行を足す（ユーザー）。同時保有は7銘柄まで。候補が空き枠より多い日は、RSの高い順を目安にユーザーが選ぶ。

### 手順T5: 記録
- 結果をObsidianに保存する（`保存・週次レビュー・QA.txt` の手順7と同じ方式、保存先は新ツール用のフォルダ）。
- 著者の判定とその後の値動きを記録し、週次レビューで「どの著者の判定が当たったか」を集計する。形の判断（ローソク足の形、VCP、ステージ）はバックテストできないため、この運用記録で評価する。

## 2-3. 週次レビュー（毎週土曜 8:05 JST のRoutine。依頼されたときも同じ手順）

ユーザーは居合わせないので、途中で質問しない。
1. `git fetch origin claude/pensive-bell-rubzj1 && git checkout -B theme origin/claude/pensive-bell-rubzj1`
2. `D=/tmp/theme_review/$(TZ=Asia/Tokyo date +%F); mkdir -p "$D"; git fetch origin claude/ecstatic-tesla-660dhs && git archive origin/claude/ecstatic-tesla-660dhs テーマ監視 | tar -x -C "$D"`（毎朝の記録を取り出す。記録がまだない場合は「記録なし」と報告して終わる）
3. 今週分と累計の2つを作る:
   `tools/theme_review.py review "$D/テーマ監視" --since $(TZ=Asia/Tokyo date -d '7 days ago' +%F) --out "$D/week.md"`
   `tools/theme_review.py review "$D/テーマ監視" --out "$D/all.md"`
   `{ echo "# 今週"; cat "$D/week.md"; echo; echo "# 運用開始からの累計"; cat "$D/all.md"; } > "$D/review.md"`
4. 保存（2か所）: リポジトリのブランチ `claude/ecstatic-tesla-660dhs` の `テーマ監視/週次レビュー/YYYY-MM-DD.md`（必ず行う。このブランチへのプッシュはユーザーが許可済み）と、Google Driveの `株式分析/テーマ監視/` に `YYYY-MM-DD_週次レビュー.md`（Drive連携ツールが使えない場合は省略し、その旨を書く）。
5. 出力: 1行目（通知に表示される）に、今週の候補の件数と、著者の結論ごとの平均の損益（【注文する】【見送る】）を書く。続けて review.md を全文表示し、最後に「■Claudeの見解」を5行以内で付けてよい（`CLAUDE.md` の週次レビューと同じ扱い。数値の読み方に限り、個別銘柄の売買判断は書かない）。
6. 何週か記録がたまったら、著者の【見送る】が損失を避けていたか（見送った候補の成績が注文した候補より悪いか）で、方式Bの著者の役割が役に立っているかを確かめる（見解に書く）。
