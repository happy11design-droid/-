## 1. 背景

  1. 選びすぎ（過剰最適化）の確率を数字で出す方法
  2. メタラベリング（今のルールの合図はそのままにして、取るか・大きさを別に決める）

## 2. 4つの設計

### M1. 選びすぎの確率を数字で出す
- 例: 組み合わせを分けて確かめる方法で、選んだ形が別の期間で中央より下になる確率を出す（Bailey・Borwein・López de Prado・Zhu 2014、CSCV／PBO）。試した数で割り引いた成績（Bailey・López de Prado 2014）、ホワイトの検定・ハンセンの検定（White 2000、Hansen 2005）も候補。
- 使うもの: すでにある結果のファイル。1年の区切りの書き出し（`backtest_retest.py` の OPT_ROLL）は、形ごと・始める日ごと・乱数ごとの1年の損益を持っている。`~/.cache/stock_backtest/results/` の `allforms_screen_87.json`・`_free.json`（417形のふるい）、`*roll_87.json`・`*roll_free.json`、`combo_feat_*.json`（14,951通りの状況の元の合図）など。キャッシュは `python3 tools/backtest_cache.py restore` で戻る。
- 書いてほしいこと:
  1. 私たちのデータの形（1年の区切りの損益の表）に合わせた計算の手順（式・分け方の数・物差し）
  2. 今の「厳しい採用の目安」（`新分析ツール/バックテストによる改善のまとめ.md` 5節）に、どう足すか。例: 選びすぎの確率が x 未満、という目安を足す。足すかどうかはユーザーが決める
  3. あなたの手1〜手9の判定に、どう当てるか
  4. （できれば）417形のふるいの結果に当てた計算。既にある結果のファイルを読んで数える計算は、してよい。数分で終わる範囲で

### M2. メタラベリング（合図の後に、取るか・大きさを別に決める）
- 考え方: 今の4つのルールが合図を出す（1次）。別の小さなモデル（2次）が、その合図の当たりやすさを出し、それで2倍ETFか元の株か（または金額）を決める（López de Prado 2018）。今の方式B（買いはルール、著者は止める理由だけ判定）や、手4と同じ形。
- 守ること（記録の失敗の型）:
  - 見送る・待つ形は年率を下げた（失敗の型4）。そのため、2次のモデルは**大きさ（2倍ETFか元の株か）だけ**に使う。
  - 数値は8個まで、先に決める。モデルはロジスティック回帰など、単純なもの。
  - 売買の期間が重なるので、期間を分けて確かめるときは、重なる分を除き、間を空ける（パージとエンバーゴ）。
  - 検証は2015年〜だけ（ユーザーの決定）。
- 使うもの: `combo_feat_87.json`・`combo_feat_free.json`（合図ごとに sym・sd・ret・stopped・rule と状況の切り口がある。87銘柄 13,334件・全業種 12,448件）、株価、`earnings.json`。
- 書いてほしいこと:
  1. 的（例: その合図が損切りで終わるか、1回の損益が上位か）
  2. 数値8個とその定義
  3. 分け方（決める期間・確かめる期間、パージとエンバーゴの日数）
  4. 2次のモデルの点数で2倍ETFか元の株かを決める閾値の決め方
  5. `backtest_retest.py` のどこに足すか（make() の lev の後で、合図ごとに L を決める）
  6. でたらめとの比べ方
  7. 採用の目安

### M3. 逐次検定（これからの記録で、早く正しく判断する決まり）
- 対象: あなたの手6（著者の判定を同じ日どうしで比べる D）、手1の記録（下げの理由の区分ごとの成績）、手7（ショックの広がり）、過熱した合図（`record.json` の hot）。どれも毎日少しずつたまる。
- 例: ワルドの逐次確率比検定（SPRT）、ベイズの逐次の判断、群逐次（αの使い方）。
- 書いてほしいこと:
  1. 対象ごとの「効いている」「効いていない」の仮説と、意味のある差の大きさ
  2. 誤りの確率（効いていないのに効いていると判断する確率、その逆）
  3. 件数ごとの判断の境目の表（例: 20件・40件・60件で、差がいくつ以上なら判断）
  4. 週次レビュー（`tools/theme_review.py`）に足す計算と表示
  5. 同じ時期に固まる記録（同じ日の候補はまとめて動く）の扱い

### M4. 合図の効き目が落ちたことを早く知る見張り方
- 例: CUSUM（Page 1954）、ページ・ヒンクリー、ベイズの変化点の見張り。
- 対象: ルールごと（押し目・急落の底・ミネルヴィニ・新高値V2）の売買の成績。毎週の実際の候補（ルールどおりに売買した場合）と、バックテストの過去の成績。
- 書いてほしいこと:
  1. 見張る数値（1回の損益、損切りの割合など）と、基準（2015年〜のバックテストの平均とばらつき）
  2. 知らせる境目と、平常時にたまたま知らせてしまう間隔（何年に1回か）
  3. 知らせたときにすること（知らせるだけ。ルールを変えるかはユーザーが決める）
  4. 2015〜2026年のバックテストの売買に当てたら、いつ知らせたか（できれば計算。既にある売買の一覧（`backtest_retest.py` の OPT_TRADELIST、`combo_feat_*.json`）を読むだけで数分で終わる範囲で）。2022年以降に短期の逆張りが消えたこと（上下判定ツール）や、AIを先に買う形が負けた年（2016〜2018・2023年）を、早く知らせられたか
  5. 週次レビューへの足し方
