
毎朝の「相場天気予報」を作成する手順。平日7:00 JSTにRoutineから自動実行される。
チャート画像は不要。個別銘柄の分析（チャート分析.txt 手順1〜6）は実行しない。

## 適用範囲と禁止事項（最初に必ず読むこと）

この手順で扱うのは**米国株・日本株の市場全体（マクロ環境）のみ**である。

- **個別銘柄の売買判断（買い／売り／様子見）を書いてはならない。** 個別銘柄の判定は `チャート分析.txt` の手順に従いNotebookLMの著者ペルソナが行うものであり、この天気予報の役割ではない。
- 個別銘柄に言及してよいのは、「その日の市場全体を動かした要因」として事実を述べる場合のみ（例: 「エヌビディアの決算を受けて半導体セクターが上昇」）。そこから「だから買い」といった判断へ進んではならない。
- **この天気予報で述べたClaudeの相場観を、`チャート分析.txt` 手順5-3のNotebookLMプロンプトに混ぜてはならない。** プロンプトへ渡すのは数値・事実のみとし、Claudeの解釈は渡さない。著者ペルソナがマニュアルではなくClaudeの相場観に影響されることを防ぐため。
- **手順6「■Claudeの総合見解」の前提としても使わない。** 総合見解はあくまで各ノートブックの回答を横断比較して構成する。

## 手順W-0: 効率ルール（最初に必ず読むこと）

このレポートは毎営業日自動実行されるため、1回あたりのトークン消費を抑えることが品質と同じくらい重要である。以下を厳守する。

- **`チャート分析.txt` を読んではならない。** この手順書は自己完結しており、必要なコマンド・項目はすべてここに書いてある。あの手順書は個別銘柄分析用であり、天気予報には不要。
- **WebSearchの回数は通常3〜4回まで**（テーマ全体や指数が大きく下げた日、および指数・商品が大きく動いた日（上昇を含む。W-1-2 の「大きく動いた日」）は、その原因を調べる追加の分だけ増やしてよい）。 内訳はW-1-2（変動理由）で1〜2回、W-1-3（予定イベント）で1回、W-1-4（センチメント）で1回。W-1-0の判定により指標の更新が必要な日のみ、その項目分だけ追加してよい。
- **レポートファイルは一度だけ書く。** 書き直し・誤字修正のための再コミットはしない（軽微な誤字は許容する）。
- **取得した値の再検証・裏取りのための追加検索をしない。** 1つの情報源で取得できた値をそのまま使い、出典が食い違う場合のみその旨を1行添える。
- **思考過程・中間報告をチャットに長々と書かない。** 最終レポートと保存先の報告のみを出力する。

## 手順W-1: データの取得

### W-1-0: 前回レポートからの経済指標の引き継ぎ（最重要・トークン削減の要）

リポジトリの `相場天気予報/` フォルダから**直近の既存レポート**（今日以外で最も新しい日付のファイル）を1つ読む。存在しない場合のみ、W-1-5の全項目を新規に検索する。

存在する場合、そのレポートの「## 直近の経済指標」セクションを**原則そのまま引き継ぐ**。これらは月次・四半期の発表であり、毎日検索し直すのは純粋な無駄である。

引き継いだ各項目について、**本日が「次回発表予定日」を過ぎているかどうかだけ**を判定する（前回レポート内に発表予定日が書かれている。例:「9月分は10/14発表予定」）。

- 発表予定日をまだ過ぎていない → **検索せず、前回の記述をそのまま転記する。**
- 発表予定日を過ぎている、または予定日が不明 → その項目**のみ**をWebSearchで更新する。
- 引き継いだ項目には、本文中に `（前回レポートより引き継ぎ、YYYY-MM-DD取得）` と明記する。

### W-1-1: 米国主要3指数の終値と変動理由
手順2-1のYahoo Finance v8 APIで取得する指数に加え、S&P500（`%5EGSPC`）を必ず含めること。以下をそのままコピーして実行してよい。

```bash
UA="Mozilla/5.0"
for S in "%5EDJI:NYダウ" "%5EIXIC:NASDAQ" "%5EGSPC:S&P500" "%5ESOX:SOX指数" "%5EVIX:VIX指数" "NIY=F:日経平均先物(CME円建)" "1357.T:日経ダブルインバース(1357)" "JPY=X:ドル円" "%5ETNX:米10年債利回り" "2YY=F:米2年債利回り" "CL=F:WTI原油" "GC=F:金"; do
  SYM="${S%%:*}"; NAME="${S##*:}"
  curl -sS --max-time 15 -H "User-Agent: $UA" "https://query1.finance.yahoo.com/v8/finance/chart/${SYM}?interval=1d&range=1d" 2>/dev/null \
  | NAME="$NAME" python3 -c "
import sys,json,os
try:
    m=json.load(sys.stdin)['chart']['result'][0]['meta']
    print(f\"{os.environ['NAME']}: {m['regularMarketPrice']} ({m['regularMarketChangePercent']:+.2f}%)\")
except Exception:
    print(f\"{os.environ['NAME']}: 取得不可\")
"
done
```

### W-1-2: 変動理由のニュース検索
**最初に、ニュースの見出しを取る（WebSearchの回数に数えない。約3秒。2026-10-20 ユーザー決定）。**
```bash
python3 tools/news_headlines.py day <昨晩の米国の取引日 YYYY-MM-DD>
```
Googleニュース（日付を指定）の見出しが、日付・媒体名付きで並ぶ（市場全体の英語・日本語のまとめ記事、半導体・AI株、信用（社債）、「〇〇ショック」の呼び名）。
見出しで材料が分かったもの（例: 「米国株式市場＝反落、ＡＩ関連株の売り継続 コアウィーブ12％安」ロイター）は、その媒体と日付を出典として書き、同じことをWebSearchで調べ直さない。
**続けて、原油・地政学・政権の発言・金利・為替・アジア欧州・日本市場の見出しを取る（WebSearchの回数に数えない。2026-11-10 ユーザーの指示）。**
```bash
python3 tools/news_macro.py day <昨晩の米国の取引日 YYYY-MM-DD>
```
月曜の米国市場（金曜の引け後〜月曜）は、土日の出来事で動くので、このコマンドが前の土日の見出しも自動で含める。
2026-11-09（月）にダウが1,104ドル高、SOXが+6.9%と急反発した理由を、市場まとめの見出しだけを見て「売られ過ぎからの買い戻し」「原油の下げの理由は特定できず」と書いた。実際は、トランプ氏がイランへの再攻撃の可能性を否定（原油が約5%急落、インフレ・利上げ観測が後退）という土日から月曜の材料が主因だった。`news_headlines.py` は株の市場まとめ・半導体・信用・ショックの呼び名しか取らず、原油・地政学・金利・政権の発言を取っていなかった。
WebSearchは、見出しで材料が分からないときと、数字・発言の中身を確かめるときだけ使う（広い言葉の検索を重ねても1社ごとの出来事は出てこない。2026-10 の東芝・CXMT・Broadcomの発言・Anthropicを見落とした）。
大きく下げた銘柄が分かっているときは `--tickers CRWV,MU` のように足すと、その銘柄の見出しも並ぶ。
引け後の決算・発言で時間外に動いた銘柄は、見出しの「引け後・時間外の動き」で確かめ、AI・半導体など大型株に波及していれば、そのつながり（何が出て、どこが時間外にどれだけ動いたか）を書く（2026-10-21 ユーザーの指示。10/20 は Super Micro と SpaceX の決算で、AI半導体が時間外に約+2%上げた）。

**指数や商品が大きく動いた日（ダウ・NASDAQ・S&P500のどれかが±1.5%以上、SOXが±3%以上、WTI原油が±3%以上、金が±2%以上、ドル円が±1%以上、米10年債が±5bp以上、のどれか）は、上昇・下落のどちらでも、動いた全部の項目について原因を書く（2026-11-10 ユーザーの指示）。**
1. 動いた項目ごとに、見出しで確認した具体的な出来事（誰が・何を発表／発言し、いつ）と出典（媒体・日付）を書く。原油・金・金利・ドル円が動いたのに理由を書かないのは不可。
2. 理由が見出しに無いときは、`news_macro.py` の見出しの検索語に近い言葉を変えて、WebSearchを最低2回（日本語と英語、または日付・銘柄を変えて）行う。1回の検索で古い記事しか出なかっただけで「特定できず」と書かない。Google ニュースを日付付きで直接引く方法も使える（`news_macro.py` が使っている `google()` を参照）。
3. 「売られ過ぎからの買い戻し」「地合いの改善」「リスクオン」のような、見出しの裏付けがない説明を原因として書かない。書くときは「（推測）」と明記し、どの見出しからの推測かを書く。
4. それでも特定できない項目は、「特定できず」と書き、試した検索（見出しの分野・検索語・回数）を1行で添える。
5. 原油・金・金利・ドル円と株の動きのつながり（例: 原油安→インフレ懸念の後退→利上げ観測の後退→株高）が見出しで確認できれば、そのつながりを書く。
6. 相場全体に効く「今続いている大きな出来事」（2026-11 時点はイラン戦争・ホルムズ海峡・原油、FRBの追加利上げ観測、中間選挙後のAI規制）は、毎回レポートの冒頭近くで一言触れ、前回から何が変わったかを書く。
そのうえで、昨晩の米国市場が上昇／下落した理由を書く。「セクター全体が」「地合いが」といった説明で止めず、**具体的な材料（経済指標の結果、要人発言、個別大型株の決算、地政学イベント等）を特定すること。** 特定できない場合は「明確な材料は特定できず」と明記する。
**テーマ全体（半導体・AI など）や指数が大きく下げた日（SOX・NASDAQが−2%以下、またはSOXが3日で−5%以下）は、回数の上限（W-0）を超えてよいので、次も必ず確かめる（2026-10-16 ユーザーの指示。10/14 のCoreWeaveの社債急落＝AI関連の信用不安を見落としたため）。まず見出し（上のコマンド。下げた銘柄を `--tickers` に足す）で確かめ、見出しで分からないものだけWebSearchで調べる。何で確かめたかを書く。**
1. 一番大きく下げた大型株を2〜3社、銘柄名で検索する（業界の言葉だけで済ませない）。
2. 信用の材料（社債の利回り・CDS・格付け・増資・資金調達・プライベートクレジット）を検索する。
3. ハイイールド債（HYG）と VIX の動きで、市場全体に広がっているかを書く。
4. 報道で「〇〇ショック」と名前が付いていれば、その名前と出典を書く。

### W-1-3: 本日の予定イベント
本日から翌営業日にかけて予定されている、相場を動かしうるイベントを検索する（経済指標の発表、FOMC・日銀会合、主要企業の決算、指数の定期入れ替え等）。日本時間での予定時刻とあわせて記載する。**WebSearchは1回にまとめること。**

### W-1-4: センチメント指標（毎日更新、WebSearch 1回にまとめる）
以下2項目は日々変動するため毎回取得する。ただし**1つのクエリにまとめて検索**し、2回に分けない。
- 米国 Fear & Greed Index（CNN）: 現在値と分類
- 日経VI（日経平均ボラティリティー・インデックス）: 現在値

WebSearchで値が出ないとき、すぐ「取得不可」にしない（2026-10-31 ユーザーの指示。10/30のレポートでF&Gを取得不可にしたため）。次を順に試す。
- Fear & Greed: CNNのデータ元は自動アクセスを拒否される。`curl -sS -L -H "User-Agent: Mozilla/5.0" https://feargreedmeter.com/` の本文から「Fear and Greed Index is currently at NN (...)」を読む（第三者サイトの再掲なので、CNN本体の値ではない旨と日付の不確実性を書く）。
- 日経VI: 日経・投資ドットコムは自動アクセスを拒否する。日本語で「日経VI 終値 <日付>」を検索し、それでも出なければ「取得不可」と書く。

### W-1-5: 経済指標の一覧（W-1-0で「更新が必要」と判定された項目のみ検索する）
この一覧が経済指標のマスターリストである。`チャート分析.txt` を参照する必要はない。W-1-0の引き継ぎ判定で更新が必要になった項目**のみ**を検索し、それ以外は前回レポートから転記する。

- 米雇用統計（非農業部門雇用者数・失業率、直近発表分。原則毎月第1金曜発表）
- FOMC（直近会合の政策金利および声明の要旨。年8回）
- FOMCドットチャート（政策金利見通しの中央値。3・6・9・12月の会合で更新）
- 米GDP（直近四半期の実質成長率、前期比年率）
- CPI（米消費者物価指数、総合・コアの前年同月比。毎月中旬発表）
- ジャクソンホール会議（直近開催時の要旨。年1回・8月）
- PMI（ISM製造業・非製造業、直近値。毎月上旬発表）
- 日銀短観（業況判断DI。年4回・4/7/10/12月初旬発表）

WebSearchで数値が出ない経済指標は、FREDのCSVを `curl -sS "https://fred.stlouisfed.org/graph/fredgraph.csv?id=<ID>" | tail -4` で取る（ID: GDP成長率 A191RL1Q225SBEA、PCE価格指数 PCEPI、コアPCE PCEPILFE、新規失業保険申請件数 ICSA、CPI CPIAUCSL、失業率 UNRATE、非農業部門雇用者数 PAYEMS）。物価指数は水準で出るので、前月比・前年比は自分で計算し、「FRED」を出典に書く。

各項目は必ず「値・発表日」を明記し、取得できなかった項目は推測で埋めず「取得不可」と明記する。次回発表予定日が判明した場合は必ず併記すること（次回以降の引き継ぎ判定に使うため）。

## 手順W-2: 天気の判定

取得したデータを総合し、本日の相場の「天気」を判定する。判定は以下を**目安**とし、機械的な当てはめではなく総合的に行うこと。根拠となった指標を必ず併記する。

- **晴れ**: 主要指数が上昇、VIX・日経VIが低位安定、Fear&Greedが中立〜強欲、金利が落ち着いている
- **曇り**: 指数がまちまち、ボラティリティ指標が中程度、方向感を欠く
- **雨**: 主要指数が下落、VIX・日経VIが上昇、Fear&Greedが恐怖圏、金利急騰やクレジット不安などの警戒材料がある
- **雷雨**: 上記に加え、急落・パニック的な値動き、地政学リスクの顕在化等

「曇りのち晴れ」のように、日中の変化が見込まれる場合は併記してよい。

**判定できるだけの材料がない項目は、推測で埋めず「判定材料なし」と明記すること。**

## 手順W-4: 保存

**重要: 以下W-4-1（リポジトリ保存）を必ず最初に、他の何より優先して実行すること。** Routineから起動されたセッションは実行環境が使い捨てで、このステップを終える前にセッションが終了すると、それまでの作業がすべて失われる。Google Drive保存（W-4-2）を先に試みて失敗や迷いが生じ、リポジトリ保存が後回しになって結局実行されない、という事態を過去に一度起こしている。**Drive保存の成否に一切関わらず、W-4-1は無条件・最優先で完了させること。**

### W-4-1: リポジトリへ保存（最優先・無条件・キャッシュ兼用）
天気予報のレポートを作成したら、他の作業（Drive保存の試行等）に入る前に、直ちに以下を実行する。

1. リポジトリ直下の `相場天気予報/YYYY-MM-DD.md` にレポート本文を書き込む。
2. 以下を実行し、**コマンドの出力を確認してエラーが出ていないこと**を確かめる（出力を確認せず次に進まない）。
   ```bash
   git add "相場天気予報/YYYY-MM-DD.md"
   git commit -m "相場天気予報 YYYY-MM-DD"
   git push -u origin claude/ecstatic-tesla-660dhs
   ```
   カレントブランチが `claude/ecstatic-tesla-660dhs` でない場合は、先に `git fetch origin claude/ecstatic-tesla-660dhs && git checkout claude/ecstatic-tesla-660dhs` を実行してから上記を行うこと。
3. `git log -1` の出力を確認し、コミットが実際に作成され、`git push` がエラーなく完了したことを検証してから、次のW-4-2へ進む。**この検証が終わるまでW-4-2（Drive保存）に着手してはならない。**

これは人が読むためだけでなく、**同日中の個別銘柄分析が手順2-2の再取得を省略するためのキャッシュとして使う**（`チャート分析.txt` 手順2-3を参照）ため、他のどの保存よりも優先度が高い。

### W-4-2: Obsidian（Google Drive）へ保存
