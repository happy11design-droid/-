
以下の手順を、順番通り・省略せずすべて実行してください。

## 手順0: 一部ノートブックの分析要否確認（他のどの手順よりも先に、必ず最初に確認する）
チャート分析の依頼を受けたら、画像の取得や経済指標の検索などの作業に入る前に、まずユーザーへ以下をYES/NO形式で確認すること。
「Claude_新高値ブレイク投資術」と「Claude_株空売り 5つの戦術」の2つのノートブックも、今回の分析対象に含めますか？（YES/NO）

- **YESの場合**: この2つも含め、対象ノートブックすべてを手順4〜5の通常フローでそれぞれ独立に並行分析する（他のノートブックと全く同じ扱いで、5-1〜5-4を個別に実行し、それぞれの結果を個別に表示する。統合や合成は行わない）。
- **NOの場合**: この2つを手順4の対象ノートブック一覧から除外し、分析を実行しない（NotebookLMへの送信回数が減るため、その分だけ回答時間を短縮できる）。それ以外の対象ノートブックは通常通り分析する。

ユーザーの回答が得られるまで手順5（NotebookLMへの送信）には進まないこと。ただし手順1〜3（画像確認・経済指標検索・ファンダメンタルズ検索）はこの質問への回答を待たずに並行して進めてよい。

## 手順1: 画像の取得（チャット添付経由）
ユーザーがこのチャットに直接添付したチャート・出来高の画像ファイル（png/jpg/jpeg）を分析対象とする。添付された画像は自動的にこのセッションの作業領域にファイルとして保存されるため、そのファイルパスをそのまま以降の手順（手順5-2の画像追加など）で使用する。Google Driveの参照やブラウザ操作は一切不要。

### 1-1. 添付画像の確認
このチャットに添付された画像ファイルすべてを対象とし、その絶対パスを控える（システムリマインダー等でパスが明示される）。画像が1枚も添付されていない場合は、分析を進めず、ユーザーにチャート画像の添付を依頼して待つこと。

## 手順2〜3の実行方式（コンテキスト節約のため必ず守ること）

手順2・手順3のデータ収集は、**必ず単一のサブエージェント（Agentツール）に丸ごと委譲して実行すること。** メインの会話で直接WebSearchを実行してはならない。

理由: WebSearchの生の検索結果は1件あたり数千トークンあり、10件前後実行するとそれだけでメインの文脈を3万トークン以上消費する。分析の本体はNotebookLM側で行われるため、メイン会話が保持すべきなのは整形後のサマリーだけでよい。

サブエージェントへの指示に必ず含めること:
- 手順2-1（Yahoo Finance APIのbashコマンド）、手順2-3（天気予報キャッシュの確認と引き継ぎ）、手順2-2の残り項目、手順3の全項目を実行する
- 検索結果の生データや作業経過は返さず、**手順3-1の「■取得データサマリー」の形式に整形したテキストだけを返す**
- 取得できなかった項目は推測で埋めず「取得不可」と明記する
- 手順3-2の送信前チェック6項目を自分で実施し、その結果も1行で返す

**あわせて、このサブエージェントの起動と同時に、以下2つをメイン側で並行実行すること。** データ収集の完了を待ってから始めると、その分だけ全体の所要時間が延びる。
1. 手順4のNotebookLM認証（手順A）。認証には60秒以上かかることがある。
2. 手順5-1・5-2の画像ソース差し替え。この処理は取得データに依存しないため、データ収集の完了を待つ必要がない。

## 手順2: 経済指標・マクロ環境データの取得（上記の通りサブエージェント内で実行）
分析対象データを補強するため、以下のデータを取得する。取得方法が2種類あるので、**手順2-1（API）と手順2-2（WebSearch）を並行して実行すること。** 各項目は「値・発表日（または取得日時）」を明記し、取得できなかった項目は推測で埋めず「取得不可」と明記すること。

### 手順2-1: 価格・指数データの取得（Yahoo Finance APIを使用）
株価・指数・為替・債券利回りといった「気配値」系のデータは、**WebSearchでは取得できないか、数日古い値しか得られないことが実績として確認されている**（日経平均先物・日経平均ダブルインバースは3回連続で取得不可だった）。これらはWebSearchを使わず、以下のコマンドで一括取得すること。以下をそのままコピーして実行してよい。

```bash
UA="Mozilla/5.0"
for S in "%5EDJI:NYダウ" "%5EIXIC:NASDAQ" "%5ESOX:SOX指数" "NIY=F:日経平均先物(CME円建)" "1357.T:日経ダブルインバース(1357)" "JPY=X:ドル円" "%5ETNX:米10年債利回り" "2YY=F:米2年債利回り"; do
  SYM="${S%%:*}"; NAME="${S##*:}"
  curl -sS --max-time 15 -H "User-Agent: $UA" "https://query1.finance.yahoo.com/v8/finance/chart/${SYM}?interval=1d&range=1d" 2>/dev/null \
  | NAME="$NAME" python3 -c "
import sys,json,os
try:
    m=json.load(sys.stdin)['chart']['result'][0]['meta']
    print(f\"{os.environ['NAME']}: {m['regularMarketPrice']} ({m['regularMarketChangePercent']:+.2f}%)\")
except Exception:
    print(f\"{os.environ['NAME']}: 取得不可\")
"
done
```

取得後、**逆イールドを必ず計算して明記すること**: `米10年債利回り − 米2年債利回り`。結果がマイナスなら「逆イールド発生中（リセッション警戒）」、プラスなら「順イールド」と併記する。

注意:
- 認証が必要なエンドポイント（`v7/finance/quote`、`v10/finance/quoteSummary`）は「Invalid Crumb」等で失敗する。使用するのは上記の `v8/finance/chart` のみとすること。
- このAPIが失敗した場合に限り、WebSearchでの取得にフォールバックしてよい（その場合は値が数日古い可能性がある旨を明記する）。

### 手順2-2: 経済指標・ニュースの取得（WebSearchを使用）
以下は発表文・統計・ニュース由来のため、WebSearchで取得する。**1件ずつ順番にではなく、同時並行で検索すること。**

**検索回数削減のため、関連性の高い項目はまとめて1つのクエリで検索してよい。** 目安として以下のようにグループ化し、同時並行で数クエリ程度に集約すること（グループ分けは目安であり厳密な指定ではない）。ただし集約した場合でも、結果からは各項目の値を漏れなく個別に抽出・記載すること。
- グループ例1: 米雇用統計・FOMC（政策金利・ドットチャート）・CPI
- グループ例2: ジャクソンホール会議・PMI（ISM製造業・非製造業）・米GDP
- グループ例3: 日銀短観
- グループ例4: 米国Fear & Greed Index・日経VI

対象項目:
・米雇用統計（非農業部門雇用者数・失業率、直近発表分）
・FOMC（直近会合の政策金利および声明・見通しの要旨）
・FOMCドットチャート（直近の経済サマリー/Projection Materialsにおける政策金利見通しの中央値。年末時点・翌年時点の水準。3・6・9・12月の会合で更新される）
・米GDP（直近四半期の実質GDP成長率、前期比年率）
・CPI（米消費者物価指数、直近発表値・前年同月比。総合とコアの両方）
・ジャクソンホール会議（直近開催時の要旨・重要発言があれば）
・PMI（ISM製造業PMI・非製造業PMI、直近値）
・日銀短観（直近調査の業況判断DI）
・米国 Fear & Greed Index（CNN、現在値と分類）
・日経VI（日経平均ボラティリティー・インデックス、現在値）

手順2-1・手順2-2で取得した内容は、後の手順5-3でファイルに書き出し、`tools/build_prompt.sh` が送信プロンプトの「経済指標・市場データ」欄へ差し込む。

### 手順2-3: 当日の相場天気予報からのキャッシュ再利用（時間短縮）
毎朝の相場天気予報（`相場天気予報.txt` により平日7:00 JSTに自動実行）が同日中に既に作成されている場合、その結果を再利用して手順2-2の再検索を省略してよい。判断基準は以下の通り。

1. リポジトリ直下の `相場天気予報/<本日の日付>.md` が存在するか確認する（存在しなければキャッシュなしとして通常通り手順2-2を全項目実行する）。
2. 存在する場合、**手順2-2（WebSearch由来の経済指標）のみ再利用してよい**: 米雇用統計、FOMC、FOMCドットチャート、米GDP、CPI、ジャクソンホール会議、PMI、日銀短観。これらは月次・四半期の発表であり日中に変化しないため。
3. **以下は再利用せず、必ず取り直すこと。**
   - **手順2-1の全項目（株価指数・為替・金利）**: 刻々と動くうえ、Yahoo Finance APIの1コマンドで数秒で取得できる。朝7時の値で夜間の判断をしてはならない。
   - **米国Fear & Greed Index、日経VI**: 日中に変動する。ただし当日中かつ取得から数時間以内であれば再利用してよく、その場合は取得時刻を必ず明記する。
   - **手順3の全項目（個別銘柄のファンダメンタルズ・ニュース）**: 銘柄依存であり、天気予報には含まれない。特に「現在値」は騰落率計算の基準となるため、必ず最新を取得すること。
4. 再利用した項目は、手順3-1の「■取得データサマリー」において `（本日7:02取得のキャッシュを再利用）` のように**取得時刻とキャッシュである旨を必ず明記すること。** どの値が新鮮でどの値がキャッシュかが読み手に分からない状態にしてはならない。
5. **天気予報に書かれたClaudeの相場観（「■Claudeの相場観」の節）は、再利用の対象外である。** 手順5-3のプロンプトへ混ぜてはならず、手順6の総合見解の前提としても使わない。プロンプトへ渡すのは数値・事実のみとする。

## 手順3: 銘柄ファンダメンタルズ・数値情報の取得（並行実行）
ユーザーが「（証券コード）で」のように銘柄を指定した場合、その証券コードについてWebSearch等でGoogle Finance等から以下の情報を取得する。**各項目を1件ずつ順番にではなく、同時並行で検索すること。** 値には取得日時を明記し、確認できなかった項目は推測で埋めず「取得不可」と明記すること。ユーザーが証券コードを指定していない場合（画像のみでの依頼の場合）は、本手順は省略し「特になし」として扱う。

対象項目:
・現在値、始値・高値・安値、出来高
・時価総額
・PER（株価収益率、実績PER/LTM）
・予想PER（FWD PER、来期予想利益ベース）: `quoteSummary`等の認証必須APIは使わず、Yahoo Financeの銘柄ページHTML（`https://finance.yahoo.com/quote/<証券コード>/`）に埋め込まれた `forwardPE` の値を取得する。以下のコマンドをそのままコピーして実行してよい（AAPL/MSFT/DELL等で動作確認済み）。ページ内のJSONはエスケープされたダブルクォート（`\"`）を含むため、そのまま解析すること。

```bash
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Safari/537.36"
curl -sS --max-time 20 -H "User-Agent: $UA" "https://finance.yahoo.com/quote/<証券コード>/" 2>/dev/null \
| python3 -c "
import sys,re
html = sys.stdin.read()
m = re.search(r'forwardPE\\\\?\":\s*\{\\\\?\"raw\\\\?\":\s*([0-9.]+)', html)
print('予想PER(FWD PER): ' + (m.group(1) if m else '取得不可'))
"
```

このコマンドで取得できなかった場合のみ、WebSearchでのフォールバックを試み、それでも取得できなければ推測で埋めず「取得不可」と明記する。
・企業概要
・直近決算（売上高・利益の成長率など）
・過去8四半期（2年分）のBeat/Miss履歴: 各四半期について「EPS」「売上高」「次期ガイダンス」がコンセンサス予想をBeat（上回った）かMiss（下回った）かを調査し、`Beat n回／Miss m回（対象n+m期）` の形で集計を明記する。可能なら直近から順に各期の結果も列挙する。8期分すべて取得できない場合は取得できた期数を明記すること（例:「直近6期分のみ取得、Beat 4回／Miss 2回」）。推測で埋めず、まったく取得できなければ「取得不可」と明記する
・次回決算発表予定日: 証券コード指定時は必ず調査する。取得できた場合、発表が寄り前（BMO）か引け後（AMC）かも分かれば併記する。加えて、本日の日付からその決算発表日までの日数（または「発表済み・次回未定」等の状態）を明記する。取得できなければ「取得不可」と明記する
・ニュース・アナリスト評価
・急騰・急落の背景ニュース: 以下(a)〜(d)をすべて行う。
  (a) チャート画像に写っている全期間を確認し、株価が短期間で急騰または急落している箇所（大きな陽線・陰線、出来高の急増等）をすべて洗い出す。直近の値動きだけでなく、画像に含まれる過去の急騰・急落も見落とさないこと。該当箇所が見つかった場合は、その時期を特定した上でWebSearch等により原因となったニュースを調査し、時期とあわせて簡潔に記載する。調査すべき材料のカテゴリは以下をすべて視野に入れること（以前、下線部のカテゴリを検索対象から漏らしたため急騰の主因を特定できなかった実績がある）。
    - 決算発表・ガイダンス修正
    - 材料公表（新製品、大口受注、提携、訴訟等）
    - アナリストの格上げ・格下げ、目標株価変更
    - **指数の組入れ・除外（S&P500・S&P100・NASDAQ100・Russell等）**: パッシブファンドの機械的な売買を伴い、単独で二桁%の急騰・急落を起こしうる最重要カテゴリの一つ。必ず明示的に検索すること
    - **コーポレートアクション（株式分割、自社株買い、増資・希薄化、M&A、スピンオフ、CEO・CFO交代、ロックアップ解除、大株主・インサイダーの売買）**
    - 市場全体・セクター全体の急変、同業他社の決算・ニュースの波及
    - 規制・地政学・通商政策（関税、輸出規制等）
  (b) (a)とは別に、直近の取引日の値動きの背景を特定するための検索を、**必ず複数の角度から行う**（1回の検索で止めない）。最低限、次の2種類を実行すること。
    - 「〈銘柄名または証券コード〉 株価 急騰 OR 急落 本日」のような日本語検索
    - 「〈ティッカー〉 stock surge OR drop 〈直近取引日の日付〉 why」のような英語＋日付指定の検索
    **「セクター全体が上がったから」「地合いが良かったから」といった銘柄固有でない説明しか得られなかった場合は、それを結論として採用してはならない。** 必ず検索語を変えて再検索し、その銘柄固有の材料（指数組入れ、決算、格上げ等の具体的な固有名詞を伴う事実）を特定すること。再検索しても銘柄固有の材料が見つからない場合に限り、「銘柄固有の材料は特定できず（セクター全体の動きによる可能性）」と明記する。
  (c) **チャート画像の最終日と、実際の直近取引日の終値を必ず突合すること。** 手順2-1と同じYahoo Finance v8 APIで直近5営業日のOHLCVを取得し（`range=5d`）、画像の最終日以降に取引日が存在する場合は、その期間の値動きを別途明記した上で、(a)(b)と同じ基準で背景ニュースを調査する。**画像に写っていない期間に起きた大きな値動きこそ、各ノートブックがチャートから読み取れない＝テキストで伝えるしかない情報であり、最も抜けやすく最も重要である。**
  (d) **今後予定されているイベント**（指数組入れ・除外の実施日、決算発表日、ロックアップ解除日、投資家説明会等）のうち、判明したものを日付とあわせて記載する。特に指数組入れは、実施日を境に需給が一変するため必ず記載すること。
  (a)〜(d)のすべてについて特に目立った急騰・急落・予定イベントが見つからなかった場合のみ、この項目は無理に埋めず省略してよい。

取得した内容は、後の手順5-3でファイルに書き出し、`tools/build_prompt.sh` が送信プロンプトの「銘柄ファンダメンタルズ情報」欄へ差し込む。

### 手順3-1: 取得データのユーザーへの表示（見落とし防止）
手順2・手順3で取得した内容（経済指標・市場データ、銘柄ファンダメンタルズ情報、特に(a)(b)の急騰・急落背景ニュース）は、NotebookLMへ送るプロンプトに埋め込むだけでなく、見出し「■取得データサマリー」を付けて、後述の手順5-4（各ノートブックの回答表示）より前に、ユーザーへそのまま提示すること。これは、ニュースや指標がプロンプト内に埋もれてユーザーの目に触れないまま処理が進むことを防ぐためである。要約・省略はせず、取得できた値・日時・出典をすべて含めること。取得不可の項目も「取得不可」と明記して残すこと。

### 手順3-2: 送信前の検証ゲート（重大な抜けの防止）
手順5-3で【送信プロンプト】をNotebookLMへ送信する**前に**、以下のチェックを必ず自分で行い、1つでも満たせない項目があれば送信せず、手順2・手順3に戻って追加調査すること。これは、著者ペルソナが不完全・誤った前提のまま投資判断を下すこと（過去に実際に発生した）を防ぐためのゲートである。

1. **直近の大きな値動きの原因を、銘柄固有の具体的な事実で説明できているか**: 直近5営業日以内に±5%以上の日次変動がある場合、その原因を「指数組入れ」「決算」「格上げ」等の固有名詞を伴う事実で説明できていること。「セクター高」「地合い」のような銘柄固有でない説明しかない状態で送信してはならない。
2. **チャート画像に写っていない期間の値動きを、テキストで補足できているか**: 画像の最終日と直近取引日が異なる場合、その間の始値・高値・安値・終値・出来高と、背景ニュースがプロンプトに含まれていること。
3. **「現在値」がどの日付の終値かを明記しているか**: 画像内の価格と「現在値」が異なる場合、両方の数値と日付、および乖離率をプロンプトに明記していること。
4. **手順2の全項目に値または「取得不可」が入っているか**: 空欄・未記載の項目がないこと。
5. **次回決算発表予定日と、本日からの日数が入っているか**。
6. **今後予定されているイベント（指数組入れ実施日等）が判明していれば記載されているか**。

このチェックの結果は、手順3-1の「■取得データサマリー」の末尾に `■送信前チェック: 1〜6すべて確認済み` の1行を付けてユーザーに示すこと。満たせなかった項目がある場合は、その番号と理由（追加調査しても取得できなかった旨）を明記すること。

## 手順4: 対象ノートブックの特定
`nlm notebook list` を実行する前に、必ず「補足: NotebookLM認証の更新」に従って手順Aを先に実行し、認証を更新すること。認証エラーが出るのを待ってから手順Aを実行するのではなく、**先に手順Aを済ませてから** `nlm notebook list` を叩く（NotebookLMのセッションCookieは分析依頼のたびに失効していることが多く、素で叩いて失敗するのを待つより、先に更新した方が速い）。既に認証が有効な場合でも、手順Aの再実行によるデメリットはない。
`nlm notebook list` を実行し、タイトルに「Claude」（大文字・小文字は問わない）を含むノートブックをすべて対象とする。対象ノートブックの一覧をコード側に固定せず、その時点で該当するものをすべて自動的に対象へ含めること。
手順0で「Claude_新高値ブレイク投資術」「Claude_株空売り 5つの戦術」の分析がNOと回答された場合、この2つを対象ノートブック一覧から除外する。YESの場合、または手順0自体が省略された場合は、通常通りこの2つも対象に含める。

## 手順5: 対象ノートブックへ一括送信する（`tools/run_notebooks.sh` による並列シェル実行）

**ノートブックごとにサブエージェント（Agentツール）を起動してはならない。** `nlm` コマンドを数本叩くだけの処理にサブエージェントを1件起動すると、起動時のシステムプロンプト読み込みと、ツール呼び出しのたびに発生する文脈の再読み込みで、1件あたり約57,000トークンを消費する（6件で約34万トークン。2026-09-22の実測値）。実際にメイン会話が必要としているのは各400字程度の回答本文だけであり、シェルで直接並列実行すれば同じ結果が約5,000トークンで得られる。手順2・3のデータ収集だけは、検索の生データが巨大なためサブエージェントへの委譲を維持する（上記「手順2〜3の実行方式」を参照）。

スクリプトは `nlm notebook list` のタイトルに「Claude」を含む全ノートブックを自動的に対象とし、全件を並列実行する。所要時間は最も遅い1件とほぼ同じになる。

### 5-1・5-2. 画像ソースの差し替え（データ収集の完了を待たずに先行実行する）
前回このワークフローで追加したチャート画像を、今回の画像セットへ入れ替える。テキスト・マニュアル等の画像以外のソースには触れない（スクリプトはTITLEが .png / .jpg / .jpeg で終わるソースのみを削除対象とする）。
```bash
tools/run_notebooks.sh --phase images --image "<画像パス1>" [--image "<画像パス2>" ...] [--exclude '<除外する正規表現>']
```
手順0で2つのノートブックの分析がNOと回答された場合は `--exclude '新高値ブレイク投資術|株空売り'` のように渡して除外する。

### 5-3. プロンプトの組み立てと送信
`送信プロンプト雛形.txt` を一字一句改変せず使用する。手順3で取得した銘柄ファンダメンタルズ情報（証券コード指定がない場合は「特になし」）と、手順2で取得した経済指標・市場データをそれぞれファイルに書き出し、以下で差し込む。雛形の他の文言は自動的に保持されるため、手作業での転記ミスが起こらない。
```bash
tools/build_prompt.sh "<ファンダメンタルズ情報ファイル>" "<経済指標ファイル>" "<生成先プロンプトファイル>"
tools/run_notebooks.sh --phase chat --prompt "<生成先プロンプトファイル>" --out "<出力ディレクトリ>" [--exclude '<除外する正規表現>']
```
`--exclude` には 5-1・5-2 と同じ値を渡すこと。

所要時間の目安: 全件並列のため、6冊でも1分前後で完了する。

会話履歴について: スクリプトは常に `nlm generate-chat --web` で送信する。`--web` はサーバー側の会話を使うため、やり取りがNotebookLMの画面に履歴として残り、ユーザーが後からUI上で追加の依頼（図解画像の生成など）をできる。**`--web` を外すと generate-chat は one-shot 扱いとなり、手元にしか残らずNotebookLMの画面には履歴が一切現れないので、絶対に外さないこと**（2026-09-22に実際に発生し、ユーザーがUIで「直前の判定を図解して」と依頼しても参照先が存在しない状態になっていた）。
なお履歴はノートブックごとに1本の会話へ**追記されていく**ため、別銘柄の分析を重ねると過去の銘柄のやり取りも同じ会話に残る。

**`nlm chat delete <notebook-id>` は使わないこと。** 「Chat history deleted.」と成功を返すが、実際には`--web`で作られた保存済み会話は削除されない（2026-09-22に検証済み: 削除実行の直後に生のAPIレスポンスを直接確認したところ、内容がタイムスタンプも含めてそのままサーバーに残っていた）。このRPCは「現在のデフォルトチャット」をクリアするだけで、`--web`が使う保存済み会話オブジェクトには効かないとみられる。著者が過去の銘柄に引きずられる懸念が出た場合や、履歴を消したい場合は、**ユーザー自身にNotebookLMのUIでチャットパネルから手動削除するよう案内すること。** Claude側でCLIから削除を試みてはならない。

重要な注意事項（過去に間違えた点）:
- 「投資判断マニュアル」の内容を、Claude自身が独自に抜粋・要約してプロンプトに埋め込んではいけない。マニュアルは各ノートブック内の既存ソースに含まれているので、NotebookLM自身にそのソースを参照・適用させること。
- プロンプトに「マニュアルをここに貼り付ける」といった加工は行わず、`送信プロンプト雛形.txt` をそのまま使うこと。雛形を編集してよいのは `{{FUNDAMENTALS}}` と `{{ECONOMIC_DATA}}` の差し込みのみで、これは `tools/build_prompt.sh` が行う。
- スクリプトが内部で使う `--citations off` は、文末の引用元リスト（出典番号・ソースファイル名・確信度等の一覧）の出力を抑制するオプションであり、回答本文の内容・意味を変更するものではない。

### 5-4. 結果の表示
NotebookLMから返ってきた回答を、要約・省略・言い換えを一切せず、全文そのまま（チェックリスト照合結果や表も含めて）表示すること。表示の先頭には見出し「■ノートブック：〈ノートブック名〉」を付け、どのノートブックの回答かを明示すること。Claudeが自分の言葉でまとめ直してはいけない。

## 手順6: すべてのノートブックの結果を表示した後、Claudeとしての総合見解を提示する
対象ノートブックすべての回答（手順0でNOと回答され除外されたノートブックがあれば、それは含まない）が出揃ったら、最後に見出し「■Claudeの総合見解」を付けて、以下を提示すること。
・各ノートブックの投資判断（買い／売り／様子見）が一致しているか、割れているか
・割れている場合、情報源の違い（書籍本文、YouTube由来、他の関連書籍など）から考えられる理由
・それらを踏まえた、Claude自身の言葉による総合的な所見（現時点で買い・売り・様子見のどれに近いか、特に注視すべき懸念点やリスク）
・もしエントリーする場合の価格を、買い（ロング）・空売り（ショート）の両方について提示すること。それぞれ「エントリー価格」「利益確定（利確）価格」「損切り価格」の3点を具体的な数値で明記し、あわせて現在値からの騰落率（現在値比 ±○○.○%）を併記する（計算式: （各価格 − 現在値） ÷ 現在値 × 100、小数第1位まで）。基準とした現在値も明記すること。各ノートブックの回答内で言及されているエントリー値・損切り値・利確目標を踏まえつつ、Claude自身の言葉で買いシナリオ・空売りシナリオそれぞれとして整理し直すこと。現時点でどちらの方向にもエントリー条件が整っていない（様子見）場合であっても、「条件が整った場合に想定される価格帯」として買い・空売り双方を省略せず必ず記述すること。
・**あわせて、買い・空売りそれぞれについて「本日の成行判断」と「翌営業日の予約注文」を必ず分けて記述すること。** 「様子見」で終わらせると、ユーザーは引け後に注文をセットできず、翌日の寄り付きでシグナルが出ても取り逃す（実際にこの時差が発生した）。各ノートブックが手順5-4の「現状パターン」でA／B／Cのどれを選び、どの価格を予約注文・押し目監視価格として挙げたかを踏まえ、次の2行を加えること。
  - `本日の成行判断: 〈エントリー可／見送り（理由を数語）〉`
  - `翌営業日の予約注文: 〈注文種別〉○○○（現在値比 ±○○.○%）／発動条件: 〈条件を数語〉`（パターンCで押し目待ちの場合は `押し目監視価格` として記載する）
  なお「今この価格で成行注文を出すこと」と「条件成立時に発動する予約注文を引け後にセットしておくこと」は別の行為であり、後者は予測による先回りエントリーには当たらない（条件が成立しなければ約定しないため）。この区別を崩してはならない。
・**Claudeの総合判断も「注文を発注するか否か」で決めること。** 予約注文をセットすべき局面は『様子見』ではなく『買い（予約）』『売り（予約）』とする。注文を一切出さず条件の再形成を待つだけの場合のみ『様子見』とする。各ノートブックの判定を集計する際も、この基準で揃えること。
・**各ノートブックが判定を下した軸（テクニカル／ファンダメンタルズ）を区別して記述すること。** 本ワークフローの判定対象は `投資憲法.md` 第1条の通りスイングトレード（想定保有期間1日〜1ヶ月）であり、テクニカル要因が主たる判断軸となる。ある著者がファンダメンタルズ要因（PER・決算Beat履歴等）を理由に様子見としている場合は、それが当該著者のマニュアルで明示的にエントリー条件とされているものか、それとも保有期間のより長い判断軸によるものかを明記し、スイング判断としての妥当性を読み手が判断できるようにすること。
この総合見解は各ノートブックの回答を要約したものではなく、複数ノートブックを横断して比較したうえでのClaude独自の評価として記述すること。

### 手順6-2: 投資憲法に基づく数値算出（■リスク管理数値）
「■Claudeの総合見解」を提示した直後に、続けて見出し「■リスク管理数値」を付けて、`投資憲法.md` 第3条のルールに基づく**3つの数値のみ**を提示すること。

条項ごとの適合／違反の照合表および総合判定（GO／STOP）は**廃止した**。毎回ほぼ同じ内容（全ノートブックが様子見である限り常にSTOP）となり冗長なため、実際に売買判断へ使える数値だけを残す方針に変更している。

提示するのは以下の3行のみ:
1. `損切り中央値: ○○○（対象n冊）` — 手順5-4で各ノートブックが提示した損切り値の中央値。偶数件の場合は中央2件の平均。損切り値を提示しなかったノートブックは集計から除外する。
2. `利確中央値: ○○○（対象n冊）` — 同様に利確目標の中央値。複数目標を提示したノートブックは最終目標値を採用する。
3. `ポジション上限: ○○%（損切り幅○○%、買い／空売りそれぞれ）` — 手順6で提示した買い・空売りシナリオの損切り幅から、第3条の計算式 `min( 2% ÷ 損切り幅 , 15% )` で算出する。

注意点:
- **Claudeが投資憲法の内容を推測・補完してはいけない。** 第3条の計算ルールが変更されている場合は、変更後のルールに従うこと。
- `投資憲法.md` が存在しない場合、または第3条の損切り・利確・ポジションサイジングのルールが `【要記入】` のままの場合は、算出を行わず次の1行のみを表示する:
  「■リスク管理数値: 投資憲法の第3条が未記入のため算出できません。」

以下の3つは、チャート分析（手順0〜6-2）とは別のトリガーで実行される処理であり、**チャート分析の依頼を受けただけの時点では読む必要も実行する必要もない。** 該当する依頼を受けた時にのみ `保存・週次レビュー・QA.txt` を読み、そこに書かれた手順をそのまま実行すること。

## 補足: NotebookLM認証（NLM_AUTH_TOKEN / NLM_COOKIES）の更新
手順4の直前に、認証エラーの有無を問わず毎回この手順Aを先に実行すること（詳細は手順4を参照）。`nlm` コマンドが「authentication expired or invalid」等のエラーを実際に返した場合も同様に、まず以下の手順A（PC不要・VPS経由）を試すこと。手順Aが使えない場合（環境変数`NLM_VPS_CDP_BASE`が未設定、またはVPS自体が停止している等）のみ、手順B（PC必須）をユーザーに依頼する。

### 手順A: VPS経由での自動再認証（PC不要、Claude自身で実行可能）
環境変数 `NLM_VPS_CDP_BASE`（例: `wss://nlm-server-8823.com:443/nlmcdp-<秘密トークン>`）が設定されている場合、以下をClaude自身が実行してよい。

**重要（過去に間違えた点）**: 接続先は必ず `$NLM_VPS_CDP_BASE` に入っているドメイン名（`nlm-server-8823.com`）をそのまま使うこと。VPSのIPアドレス（`34.133.108.107`等、NOTEBOOKLM_SETUP.mdに記載）を直接使ったり、`/json/version`のレスポンスに含まれる`webSocketDebuggerUrl`のホスト部分（`127.0.0.1`になっている）をそのまま流用したりしては絶対にいけない。ドメイン宛のTLS証明書を使っているため、IPアドレスやドメイン以外のホスト名で接続するとTLS証明書検証エラーで必ず失敗する。UUID（`/devtools/browser/`の後ろの部分）だけを取り出し、それ以外は`$NLM_VPS_CDP_BASE`の文字列をそのまま使うこと。

1. 現在のChromeのUUIDを取得し、`$NLM_VPS_CDP_BASE`と組み合わせて接続先URLを機械的に組み立てる（以下をそのままコピーして実行してよい。手で書き換えない）。
   ```bash
   HTTP_BASE="${NLM_VPS_CDP_BASE/wss:/https:}"
   UUID=$(curl -sS "$HTTP_BASE/json/version" | grep -oE '/devtools/browser/[a-f0-9-]+' | head -1 | sed 's#/devtools/browser/##')
   CDP_URL="${NLM_VPS_CDP_BASE}/devtools/browser/${UUID}"
   echo "$CDP_URL"   # ドメイン名(nlm-server-8823.com)になっているか必ず目視確認してからnlmに渡すこと
   ```
2. `echo`で表示された`$CDP_URL`にIPアドレスが含まれていないこと（ドメイン名になっていること）を確認した上で、パッチ版 `nlm`（session-start.shが自動ビルド済み）で再認証する。
   ```bash
   nlm auth -cdp-url "$CDP_URL"
   ```
3. **成功しても認証情報は現在のシェルに自動で反映されない。** `nlm auth` は `/root/.nlm/env` へ書き出すだけであり、これを読み込まずに `nlm notebook list` を叩くと「no valid profiles found」で失敗する（2026-09-22に実際に発生）。`nlm` を直接実行する場合は、同じコマンド内で必ず先に読み込むこと。
   ```bash
   set -a; source /root/.nlm/env; set +a
   nlm notebook list
   ```
   なお `tools/run_notebooks.sh` と `tools/build_prompt.sh` はこの読み込みを内部で行うため、スクリプト経由なら意識しなくてよい。
4. もし手順2が「redirected to authentication page」「detected sign-in page」等、Googleセッション自体が切れていることを示すエラーになった場合は、VM上のChrome自体への再ログインが必要（手順Aでは解決できない）。ユーザーに、ブラウザで `http://34.133.108.107:6080/vnc.html`（VMのnoVNC、事前にVM側で `x11vnc`/`websockify` が起動している必要あり）を開いてNotebookLM専用サブアカウントに再ログインするよう依頼し、ログイン完了の報告を受けてから手順1に戻ること。これは携帯のブラウザからでも操作可能なので、PCは不要。

### 手順B: PC経由での再認証（手順Aが使えない場合のみ）
1. PCでChromeを完全終了し、`--remote-debugging-port=9222 --user-data-dir="C:\chrome-nlm-debug"` 付きで起動
2. NotebookLM専用サブアカウントで再ログインし、https://notebook.google.com を開く
3. `nlm auth -cdp-url ws://localhost:9222` で再認証
4. `nlm auth --print-env` で表示された値（クォート文字は含めない）を、claude.ai/codeの環境「分析」の環境変数欄に `NLM_AUTH_TOKEN=...` / `NLM_COOKIES=...` として貼り付け・保存
5. 保存後、間を空けずに新しいセッションで分析を再実行する
